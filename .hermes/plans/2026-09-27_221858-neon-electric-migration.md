# Neon + Electric Migration Implementation Plan
> **For Hermes:** Use OpenCode task-by-task. Execute this plan only in a separately authorized implementation session; follow each dependency, write the specified failing tests first, implement the smallest passing change, and stop at failed acceptance gates. The delegation commands below are examples, not instructions to auto-execute now.

## Goal
Replace Convex persistence, functions, scheduled execution, and reactive queries with Neon Postgres, **Drizzle ORM**, Hono application services, and self-hosted Electric sync. Preserve Clerk authentication, Hono, React/Vite/TanStack Router, the public owner dashboard, private notes, location history, Steam/Spotify integrations, CS2 processing, and realtime updates.

## Architecture
Browser → Clerk-authenticated Hono API → Drizzle → Neon is the write path. Neon logical replication → self-hosted Electric → authorization-enforcing Hono shape proxy → browser is the realtime read path. Application reactions and external work use transactional job/outbox records and a separate durable Node worker. Vercel hosts the frontend and short Hono requests; Electric and long-running Steam GC/archive work have separate persistent hosting.

## Tech Stack
Retain React 19, Vite 8, TypeScript, TanStack Router, Clerk React/backend/Hono integrations, Hono, pnpm, AWS S3 SDK, `steam-user`, and `globaloffensive`. Add `drizzle-orm`, `drizzle-kit`, `pg`/`@types/pg` for Node transactions, `@electric-sql/client` and its compatible React integration, runtime validation, Vitest, and Playwright. Pin mutually compatible versions during implementation. Use Drizzle for relational models, queries, and versioned SQL migrations; use reviewed SQL where publication, grants, constraints, or migration operations require it.

### IDs, constraints, and timestamps
- Keep imported `_id` exactly as a **text primary key**, including all FK values; generate collision-resistant prefixed UUID strings for new rows. Do not cast Convex IDs to UUID, integers, or Clerk subjects. New IDs require an explicit reverse-migration mapping during rollback.
- Retain exact `_creationTime` milliseconds in a private numeric legacy column and derive `record_created_at`; keep explicit business `createdAt` separately. Fractional milliseconds, if present, must not be silently rounded by JavaScript `Date` conversion in the archival representation.
- Convert epoch milliseconds using division by 1,000 to UTC `timestamptz`; emit numeric epoch milliseconds in compatibility DTOs where consumers expect numbers. Parse `insertedDate`/`matchTime` as ISO timestamps; preserve source strings in the encrypted migration artifact and quarantine invalid/ambiguous values.
- Steam GC `matchtime` is seconds and is already converted to ISO in `server/routes/cs.ts`; do not multiply again. Keep Steam ID64, app IDs, match IDs, share codes, and file IDs as strings to avoid precision loss.
- Audit duplicates before converting `.unique()` assumptions into SQL uniqueness: token identifiers, per-user settings/permissions/provider snapshots, and globally looked-up share codes. Convex indexes themselves are not uniqueness constraints.
- Preserve global share-code semantics initially only after duplicate/conflicting-owner review; prevent users from overwriting another user's row. Multiple users tracking the same match require an explicitly designed match/user association, not a silent change to compound uniqueness during import.
- Preserve omitted/null/empty-string/zero distinctions in migration transforms and partial-update DTOs. Current CS2 settings ignore blank updates; current Steam settings preserve omitted values. Add explicit clear-secret actions instead of interpreting masked placeholders as credentials.
- Use FK `RESTRICT` initially; no cascade deletion of imported data without a defined account-deletion policy. Constrain roles to `viewer/editor/admin/owner/relatives`; unknown values are quarantine blockers, not auto-upgraded privileges.

## 4. Authorization, credentials, and realtime contract
### Fix source defects at the trust boundary
- `locations.getLocationHistory` checks the **target user's role**, not the authenticated caller; `addLocation` merely verifies user existence. Hono must authenticate ingestion and authorize the reader; frontend gates are insufficient.
- `websiteSettings.getMyCs2Settings` returns `shareCodeAuthToken`. Replace with `hasShareCodeAuthToken` and safe settings; secrets are write-only in the UI. Never expose encrypted ciphertext via sync either.
- `hasPermission` and note reading use `rank || fallback`, misclassifying viewer rank zero. Define explicit rank lookup; `relatives` is a separate location capability, not an implicit editor/admin rank.
- `updateUserPermission` accepts arbitrary strings and does not prevent an admin granting owner to a non-owner. Validate roles, require owner for granting/removing owner, and protect the last owner transactionally. The admin UI currently targets placeholder `user123`; implement authorized user selection instead.
- Public Spotify refresh/now-playing and Steam refresh accept caller-selected IDs without sufficient ownership checks; other-user provider reads are broadly public. Restrict private/self operations and expose only the intended public owner projection.
- `saveMatchResults` can update globally shared codes without row-owner checks; GC download lacks route auth; archive accepts client-selected remote URLs. Enforce ownership/admin capabilities, validate bounded batches, restrict upstream destinations/redirects, and keep worker-only enrichment fields server-controlled.

### ACL matrix to encode in `server/auth/policies.ts`
| Resource | Read/sync policy | Write/operation policy |
| --- | --- | --- |
| Self profile/permission | Verified Clerk subject mapped to own app user; omit token identifier/email from public projections. | Idempotent self creation/profile update; only admin/owner permission service can change roles. |
| Public dashboard | Anonymous access only to explicitly selected owner's safe Steam/Spotify projection and approved now-playing data. | Refresh requires authorized self/admin or scheduler; anonymous users cannot trigger unbounded upstream work. |
| Notes | Signed-in user with permission: own notes OR allowed ranked access level; `relatives` gets no rank-based access by default. | Editor+ creates at or below own rank; note owner or admin/owner deletes. Preserve this cross-user access model intentionally. |
| Locations | Only caller role owner/relatives; self history or designated owner's history according to existing fallback intent. No arbitrary third-user history. | Dedicated ingestion credential binds to one user; reject mismatched body IDs; normal users cannot bypass ingestion policy. |
| Settings/credentials | Own safe settings/status; owner UI may remain restricted as today. Credentials never sync or return in GET responses. | Verified self settings writes under agreed UI/API policy; secret updates encrypted/hashed server-side and audited without values. |
| CS2 | Own saved matches; admin/owner operational views; any public Steam-ID view requires an explicit safe projection decision. | Authorized owner/admin initiates jobs; workers persist trusted GC/S3 outcomes. |

### Clerk and secret handling
- Keep Clerk as identity provider. Verify session signature, issuer, expiry, and configured audience/authorized party through Clerk middleware; obtain roles from the application database, not user-editable metadata or request bodies.
- Map legacy `tokenIdentifier` to verified `(issuer, subject)` using a deterministic audited mapping. Do not match by email alone or blindly split an assumed token format; quarantine unresolved identities and preserve existing user IDs.
- Make user creation and default viewer permission a single transaction with uniqueness/race tests. Remove the Convex JWT template dependency only after the old stack no longer needs it.
- Encrypt recoverable Steam API keys, Spotify refresh tokens, and CS2 auth tokens using authenticated envelope encryption with key version, nonce, and per-user/field binding. Keep encryption keys outside Postgres; restrict decryption to Hono/worker service roles.
- Hash verification-only location credentials; clarify whether legacy `locationApiPassword` has external consumers before transforming it. Current route uses global `LOCATION_API_KEY`, not that column. Preserve legacy encrypted source values for the bounded rollback window.
- Server-only configuration includes database URLs, Electric upstream secret, Clerk secret, encryption-key references, Spotify client secret, Steam credentials/API key, internal job secret, location ingestion secret, and AWS credentials. Never prefix secrets with `VITE_`, embed them in CLI examples, or log upstream URLs containing credentials.
- Spotify OAuth: generate single-use state bound to Clerk session, expiration and redirect URI; validate callback state, use fixed allowlisted origins, exchange server-side, save rotated tokens, and expose only connection status. Eliminate untrusted forwarded-host redirect construction.
- Set explicit CORS origins; current wildcard plus credentials is unsuitable. Use Clerk bearer authentication for cross-origin requests and origin/CSRF protection for cookie-authenticated writes; redact private note/location/provider payloads from logs and analytics.

### Electric shape security and convergence
- **Do not expose a private shape directly.** Electric's origin and administrative endpoints must not be reachable without service authorization; CORS alone is not access control. Browser traffic goes through named Hono routes such as `/api/sync/notes`, never arbitrary `/v1/shape?table=...` access.
- `server/sync/shapes.ts` owns fixed table/column allowlists and parameterized row predicates. `server/routes/sync.ts` resolves identity and current policy before every initial, continuation, retry, and long-poll response; clients cannot supply table, columns, ACL predicate, upstream URL, or Electric secret.
- Forward only explicitly validated protocol state (`offset`, `handle`, allowed live options); bind handles to the authorized shape context. Do not blindly copy future SDK parameter lists. If subset POST is adopted, validate its body separately and preserve the server-owned root ACL predicate.
- Publish only approved safe tables/projections; exclude `integration_credentials`, migration staging/audit secrets, and job payloads. Use physical projection tables maintained transactionally where necessary; do not assume ordinary SQL views replicate as tables or that Postgres RLS filters Electric's replication stream.
- Start with named self profile/permission, self provider snapshots, public-owner provider snapshots, authorized notes, authorized locations, own match-status, and safe settings/status shapes. No browser shape is needed for unused `tasks` or arbitrary `cs2Demos` payloads.
- Notes rank/ownership predicates are computed server-side from current DB permissions. Increment authorization version when roles change, invalidate affected streams, reauthorize before sending a completed long poll, and discard buffered unauthorized responses. Bound polls so revocation cannot leave an indefinite authorized stream open.
- Private responses use `Cache-Control: private, no-store`, appropriate `Vary`, and no shared CDN caching. Public projection caching uses its own paths/keys. Preserve Electric offset/handle/schema/control headers and status codes; strip stale content-length/content-encoding after decompression.
- On sign-out, account switch, 401/403, or permission downgrade, abort streams, clear in-memory collections and any persisted data, and rebuild authorized shapes. Cached downloaded data cannot be retroactively erased from an adversarial client; revocation must prevent future delivery.
- Hono writes return canonical IDs, operation ID, and a tested convergence marker/version after commit. UI may show an optimistic pending state, but resolves it only after the corresponding synced row/version is observed; errors restore prior state. Do not equate HTTP success with completed replication.
- Preserve loading/null/empty distinctions, sorting, deletes, reconnect, resnapshot/control messages, token refresh, and bounded retry. Do not promise global atomic snapshots across independent shapes; dependent UI renders only consistent versions where needed.
- Electric is the downstream read transport, not a mutation executor or cron system. Hono transactions update base rows, safe projections, and outbox together; workers react at least once with idempotency. No new social “reactions” feature/table is implied by application reactions.

### Rehearsal and repeatability
1. Build an encrypted, access-controlled export workflow using supported Convex snapshot export in the implementation session. 3. Transform offline with deterministic ID/field mapping and timestamp normalization; quarantine invalid dates, orphan FKs, duplicate singleton rows/share codes, unknown roles, and unresolved Clerk identities. Encrypt secrets before target insertion; no plaintext exports in Git/logs.
4. Import users first, then dependent tables into staging using batches and transactions. Upsert by preserved source ID plus manifest version; reruns must produce the same target state, not duplicate rows. Split-table/projection checks reconcile back to one original document.

7. Repeat import and reconciliation twice on fresh staging databases; inject interruption mid-batch and rerun. Perform reverse-transform tests for created/updated/deleted rows and new IDs. Record measured duration, downtime budget, restore procedure, and artifact retention.

### Cutover: use one writer and a bounded maintenance window
1. Choose a release window only after T0–T6 pass, full staging rehearsal succeeds, monitoring is live, and measured snapshot/import time fits the agreed downtime. No unproven dual-write path is required for this app.
2. Freeze **all** Convex writes at backend functions, not just the UI: browser mutations/actions, OAuth callbacks, Apple Shortcuts ingestion, manual triggers, cron execution, and in-flight GC/archive work. Pause schedules and drain jobs; verify old direct clients cannot bypass the freeze.
3. Take final consistent export after drain; record the write fence and run final deterministic import/deletion reconciliation. If a freeze cannot cover all writers, stop: implement a durable ordered change journal with deletes before attempting incremental cutover.
4. Require zero unexplained reconciliation differences. Start Electric against finalized Neon, validate shape snapshots/ACLs, and deploy the prepared Vercel/Hono build in maintenance mode. Smoke-test Clerk identity mapping, notes, location, settings, provider status, and CS2 job reads.
5. Switch traffic/config as one release boundary, keep old Convex functions write-fenced, then open Hono writes. Enable exactly one replacement scheduler. Monitor write acknowledgments, sync convergence, upstream job behavior, and ingestion retries immediately.
6. Retain source export, old deploy artifact, old credentials under restricted access, and Convex data through the agreed rollback window (proposed minimum seven days). Do not delete Convex or drop source-compatible metadata on cutover day.

### Rollback must include post-cutover writes
- Before Neon writes open: restore previous Vercel/config release, disable replacement jobs, and unfreeze Convex only after confirming no Neon-origin changes require replay.
- After Neon writes open: freeze Hono/worker/ingestion first, drain transactions, and export all changed/new/deleted records since the cutover watermark from a durable migration change journal written in the same transactions as business changes. Outbox delivery state alone is not a complete data journal.
- Reverse-transform into the retained Convex schema. Existing IDs remain usable; new Neon IDs need Convex-generated IDs and a persistent mapping, with dependent FKs rewritten. Apply users before dependents, reconcile deletes, restore credentials through a controlled server-only process, and preserve external S3 objects/provider side effects.
- Reconcile the restored source before redirecting traffic and re-enabling exactly the old scheduler. Reinitialize client caches. Never simply point an old build at stale Convex after accepting Neon writes.
- If reverse replay cannot be completed within the measured recovery target, keep writes paused and repair forward; do not discard acknowledged writes. Test this choice in rehearsal, including a credential rotation and archive side effect that cannot be “undone.”
- **T7 gate:** repeatable forward/reverse dry runs, zero unexplained diffs, verified write fence, restored auth/ACLs, and documented achievable RPO/RTO. Target RPO zero for acknowledged application writes; set RTO from rehearsal rather than claiming an unmeasured number.
