# Neon + Electric Migration Implementation Plan
> **For Hermes:** Use OpenCode task-by-task. Execute this plan only in a separately authorized implementation session; follow each dependency, write the specified failing tests first, implement the smallest passing change, and stop at failed acceptance gates. The delegation commands below are examples, not instructions to auto-execute now.

## Goal
Replace Convex persistence, functions, scheduled execution, and reactive queries with Neon Postgres, **Drizzle ORM**, Hono application services, and self-hosted Electric sync. Preserve Clerk authentication, Hono, React/Vite/TanStack Router, the public owner dashboard, private notes, location history, Steam/Spotify integrations, CS2 processing, and realtime updates.

## Architecture
Browser → Clerk-authenticated Hono API → Drizzle → Neon is the normal write path. Apple Shortcuts POST `/api/location` instead authenticates with the existing `LOCATION_API_KEY` shared secret, without Clerk, and binds the payload user ID to the configured owner. Neon logical replication → self-hosted Electric → authorization-enforcing Hono shape proxy → browser is the realtime read path. A persistent Node worker runs the three schedules and long-running Steam GC/archive work with restart-safe database progress. Vercel hosts the frontend and short Hono requests; Electric and the worker use persistent hosting.

### Required MVP and optional hardening
- Required: actual user-facing behaviors, all three jobs, relational Drizzle schema with readable reviewed SQL, explicit identity/role mapping, write-only credentials, bounded authorized realtime, optimistic UI, auditable retained-data import, backups, and tested cutover/recovery. The 56-function inventory is evidence for consolidation/retirement, not a requirement for 56 replacement endpoints.
- Start with one worker/scheduler, per-target non-overlap, persisted CS2 cursor/status, bounded retries, and observable failures. A small job-request/run table is appropriate for manual work that outlives HTTP; it does not require a general event platform.
- Optional only when demonstrated requirements justify them: transactional outbox, multi-worker leases/fencing, dead-letter infrastructure, generalized idempotency stores, and physical read projections. No operation-ID, row-version, tombstone, or mutation-receipt protocol is required for UI confirmation without a proven gap in response + reconciliation/refetch.
- Budget for always-on Electric/Neon replication, worker hosting, storage/backups and S3. Measure app-scale load first; avoid adding services/tables solely to emulate Convex internals or enterprise-scale orchestration.

## Browser experience contract (design from the visible behavior backward)
- Public dashboard: show the owner's Steam/Spotify snapshot promptly on first load; when the scheduled refresh commits, update open tabs without a page reload. Preserve the owner fallback for anonymous visitors and avoid blocking the whole page while an unrelated query loads.
- Currently playing: keep one visibility-aware ~10-second Spotify read with a shared client cache; this is external API state, not automatically a Postgres/Electric shape. Avoid the existing duplicate polling loops.
- Notes: Clerk-scoped authorized list and immediate create/delete feedback, with another open tab reflecting the change without manual refresh. A normal Hono success/error response is enough for a mutation; Electric (or a simple invalidation/refetch path if measured to be better) keeps displayed data current. No offline-first or special operation receipt promise.
- Location map/history: Apple Shortcuts POST uses its static shared secret; an authorized owner/relative with the page open sees a new point without manual refresh. Anonymous or unrelated users cannot read the history. Preserve the existing Shortcuts payload/response independently of the new SQL IDs.
- Admin/settings/CS2: button actions receive clear progress/errors and refreshed status; write-only secrets never return to the browser. A slow Steam/CS2 job runs off the request path; the page updates when its persisted status changes.
- Session changes: sign-in shows the correct user's data without a full reload; sign-out/account switch clears private collections immediately. On disconnect/reconnect, resume or refetch without showing a previous user's data. Do not promise disconnected writes or instantaneous removal of bytes already downloaded.
- Keep data access behind a small typed browser interface such as `usePublicDashboard`, `useNotes`, `useLocationHistory`, `saveSettings` and `runCs2Job`; choose Hono fetches vs Electric shapes behind that interface based on actual freshness and authorization needs. Prove the above with two-tab browser tests, an anonymous visitor, a role switch, and a Shortcuts-compatible synthetic POST before removing Convex.

## Tech Stack
Retain React 19, Vite 8, TypeScript, TanStack Router, Clerk React/backend/Hono integrations, Hono, pnpm, AWS S3 SDK, `steam-user`, and `globaloffensive`. ### IDs, constraints, and timestamps
- Recreate user rows as agreed; Clerk subject is the stable user identity under the configured issuer. Use it as the users key/FK target, or use a surrogate with a unique Clerk subject if implementation needs it. Record an auditable old user ID → verified Clerk subject → target user key mapping and rewrite retained content FKs accordingly. Never cast a Convex ID to a Clerk subject or silently associate by email.
- Keep legacy content IDs as text where useful for import idempotence/DTO compatibility; new content may use collision-resistant UUID strings. Schema redesign may change keys with an explicit source-to-target mapping. Retain old content and relationships, not the old user-row layout. No reverse migration of newly created users is planned.
- Retain exact `_creationTime` milliseconds in restricted migration metadata/archive (or a private legacy column where useful) and derive `record_created_at` for retained content; keep explicit business `createdAt` separately. Fractional milliseconds, if present, must not be silently rounded by JavaScript `Date` conversion in the archival representation. Recreated users have new row-creation timestamps with old timestamps preserved in the mapping artifact.
- Convert epoch milliseconds using division by 1,000 to UTC `timestamptz`; emit numeric epoch milliseconds in compatibility DTOs where consumers expect numbers. Parse `insertedDate`/`matchTime` as ISO timestamps; preserve source strings in the encrypted migration artifact and quarantine invalid/ambiguous values.
- Steam GC `matchtime` is seconds and is already converted to ISO in `server/routes/cs.ts`; do not multiply again. Keep Steam ID64, app IDs, match IDs, share codes, and file IDs as strings to avoid precision loss.
- Audit duplicates before converting `.unique()` assumptions into SQL uniqueness: token identifiers, per-user settings/permissions/provider snapshots, and globally looked-up share codes. Convex indexes themselves are not uniqueness constraints.
- Preserve global share-code semantics initially only after duplicate/conflicting-owner review; prevent users from overwriting another user's row. Multiple users tracking the same match require an explicitly designed match/user association, not a silent change to compound uniqueness during import.
- Preserve omitted/null/empty-string/zero distinctions in migration transforms and partial-update DTOs. Current CS2 settings ignore blank updates; current Steam settings preserve omitted values. Add explicit clear-secret actions instead of interpreting masked placeholders as credentials.
- Use FK `RESTRICT` initially; no cascade deletion of imported data without a defined account-deletion policy. Constrain roles to `viewer/editor/admin/owner/relatives`; unknown values are quarantine blockers, not auto-upgraded privileges.

## 4. Authorization, credentials, and realtime contract
### Fix source defects at the trust boundary
- **Location READ ACL bug:** `locations.getLocationHistory` checks the target user's role, not the authenticated caller. Its Hono/shape replacement must authorize the Clerk-authenticated reader; frontend gates are insufficient.
- **Separate ingestion contract:** Apple Shortcuts intentionally uses `LOCATION_API_KEY`, not Clerk. Preserve POST `/api/location` body fields (`apiKey`, `userId`, URL, coordinates and optional address fields; `full` supplies display name), server-generated ISO `insertedDate`, and HTTP 200 `{ success: true, data: { insertedDate } }`. Missing/invalid configured or supplied secret returns 401 `{ error: 'Unauthorized' }`; compare validated secrets safely. Bind `userId` to the explicitly configured owner: accept only its approved current ID or mapped legacy ID, reject other IDs with 400 `{ error: ... }`, and persist the mapped owner FK. Preserve 400 validation-error and 500 internal-error envelopes (including safe `details` where appropriate), without Convex internals; validate numeric ranges and preserve zero altitude. No Clerk session is required.
- Old direct `addLocation` merely verifies user existence and bypasses the shared-secret boundary. At cutover disable old Convex location reads **and** writes (and other retired public functions), not merely their frontend callsites; retaining the database/export for recovery must not leave callable legacy endpoints.
- `websiteSettings.getMyCs2Settings` returns `shareCodeAuthToken`. Replace with `hasShareCodeAuthToken` and safe settings; secrets are write-only in the UI. Never expose encrypted ciphertext via sync either.
- `hasPermission` and note reading use `rank || fallback`, misclassifying viewer rank zero. Define explicit rank lookup; `relatives` is a separate location capability, not an implicit editor/admin rank.
- `updateUserPermission` accepts arbitrary strings and does not prevent an admin granting owner to a non-owner. Validate roles, require owner for granting/removing owner, and protect the last owner transactionally. The admin UI currently targets placeholder `user123`; implement authorized user selection instead.
- Public Spotify refresh/now-playing and Steam refresh accept caller-selected IDs without sufficient ownership checks; other-user provider reads are broadly public. Restrict private/self operations and expose only the intended public owner projection.
- `saveMatchResults` can update globally shared codes without row-owner checks; GC download lacks route auth; archive accepts client-selected remote URLs. Enforce ownership/admin capabilities, validate bounded batches, restrict upstream destinations/redirects, and keep worker-only enrichment fields server-controlled.

### Clerk and secret handling
- Keep Clerk as identity provider. Verify session signature, issuer, expiry, and configured audience/authorized party through Clerk middleware; obtain roles from the application database, not user-editable metadata or request bodies.
- Recreate users using verified Clerk subjects and audited legacy identity linkage; do not match by email alone or blindly split an assumed token format. Recreate roles from a reviewed mapping, explicitly naming the configured owner subject and approved owner assignments. Never grant owner to the first signup or infer it from an email. Quarantine unresolved identities/roles and retain their dependent content in the protected archive until resolved; any deferred import requires explicit approval.
- Make user creation with default `viewer` in `users.role` a single transaction with uniqueness/race tests; self creation cannot overwrite a reviewed role assignment. Remove the Convex JWT template dependency only after the old stack no longer needs it.
- Encrypt recoverable Steam API keys, Spotify refresh tokens, and CS2 auth tokens using authenticated envelope encryption with key version, nonce, and per-user/field binding. Keep encryption keys outside Postgres; restrict decryption to Hono/worker service roles.
- Hash verification-only location credentials; clarify whether legacy `locationApiPassword` has external consumers before transforming it. Current route uses global `LOCATION_API_KEY`, not that column. Preserve legacy encrypted source values for the bounded rollback window.
- Server-only configuration includes database URLs, Electric upstream secret, Clerk secret, encryption-key references, Spotify client secret, Steam credentials/API key, internal job secret, location ingestion secret, and AWS credentials. Never prefix secrets with `VITE_`, embed them in CLI examples, or log upstream URLs containing credentials.
- Spotify OAuth: generate single-use state bound to Clerk session, expiration and redirect URI; validate callback state, use fixed allowlisted origins, exchange server-side, save rotated tokens, and expose only connection status. Eliminate untrusted forwarded-host redirect construction.
- Set explicit CORS origins; current wildcard plus credentials is unsuitable. Use Clerk bearer authentication for cross-origin requests and origin/CSRF protection for cookie-authenticated writes; redact private note/location/provider payloads from logs and analytics.

### Electric shape security and convergence
- **Do not expose a private shape directly.** Electric's origin and administrative endpoints must not be reachable without service authorization; CORS alone is not access control. Browser traffic goes through named Hono routes such as `/api/sync/notes`, never arbitrary `/v1/shape?table=...` access.
- `server/sync/shapes.ts` owns fixed table/column allowlists and parameterized row predicates. `server/routes/sync.ts` resolves identity and current policy on every initial, continuation, retry, and long-poll request before forwarding it; clients cannot supply table, columns, ACL predicate, upstream URL, or Electric secret. Public-owner shapes use explicit anonymous-safe policy.
- Forward only explicitly validated protocol state (`offset`, `handle`, allowed live options); bind handles to the authorized shape context. Do not blindly copy future SDK parameter lists. If subset POST is adopted, validate its body separately and preserve the server-owned root ACL predicate.
- Publish only approved safe tables/projections; exclude `integration_credentials`, migration staging/audit secrets, and job payloads. - Compute notes rank/ownership predicates from current `users.role`. Reauthorize every private shape request using Clerk and current database policy; use short, bounded private long-polls with a documented maximum duration/response size and authorization-cache TTL (prefer no role cache). Recheck policy before forwarding a completed buffered poll where feasible. Choose and test actual bounds in T3; do not leave an indefinite private stream open.
- Private responses use `Cache-Control: private, no-store`, appropriate `Vary`, and no shared CDN caching. Public projection caching uses its own paths/keys. Preserve Electric offset/handle/schema/control headers and status codes; strip stale content-length/content-encoding after decompression.
- On local sign-out, account switch, 401/403, or observed role change, abort the current stream, clear in-memory collections and persisted private caches, and rebuild authorized shapes if still permitted. A remote role change takes effect on the next server authorization check within the configured poll/request bounds. Already-authorized/in-flight bytes can unavoidably arrive during that bounded window, and downloaded data cannot be retroactively erased. Do not promise instantaneous global cancellation or require a cross-instance invalidation protocol.
- Hono writes return normal success with canonical IDs/DTOs after commit, or actionable errors. Apply immediate optimistic UI; on failure restore state/show the error, and on success let Electric eventually reconcile. HTTP success confirms the database write, not replication completion. Reconcile/refetch on reconnect, uncertain outcomes, or deletes as needed so stale rows do not reappear. No operation-ID/version/tombstone/receipt machinery unless a behavioral test proves it necessary.
- Preserve loading/null/empty distinctions, sorting, deletes, reconnect, resnapshot/control messages, token refresh, and bounded retry. Do not promise global atomic snapshots across independent shapes; use an authorized refetch when a dependent view needs a fresh coherent result.
- Electric is the downstream read transport, not a mutation executor or cron system. Hono/worker transactions update relational rows and any required safe projections; workers use retry-safe upserts and persisted progress. A transactional outbox is optional if a concrete reliable-event requirement emerges. No new social “reactions” feature/table is implied.
